# 星语 StarLang

> 一门用中文写的小语言。
> **更准确的说法：一份完整的「语言实现」记录。**

**它不打算成为生产语言。** 它想回答一个具体问题：

> **同一份语义，能不能被几个完全独立的实现忠实承载？这个「忠实」怎么机械地验证？**

这个问题在大语言里也很少被正面回答——CPython 和 PyPy 不追求逐字节一致，
V8 / SpiderMonkey / JavaScriptCore 各有各的输出细节，大家通常靠「测试套件通过」
而不是「输出完全一致」来验收。

星语的答案是：**三个独立引擎 + 一条硬标准 + 一套机械验证工具。**

---

## 三个引擎，一条硬标准

| 引擎 | 文件 | 怎么跑 |
|---|---|---|
| 树遍历解释器 | `starlang.py` | 直接走 AST |
| 编译器 | `starlangc.py` | 生成 Python 源码再 `exec` |
| 字节码虚拟机 | `starlangvm.py` | 编译成指令流，栈式执行 |

同一段程序，三边输出**必须逐字节相同**——做不到就是有 bug。

```powershell
python 对比.py                     # 30 个 demo，三方逐行比对
python 差分测试.py --个数 1000      # 随机生成 1000 个程序，三方比对
python 全检.py                      # 一条命令跑完所有验证
```

不是「大概一致」，是机械核对。**这条标准逼出了下面一整张表。**

---

## 它抓到了什么

这是这个项目最有价值的产出——不是语言本身，是**这些 bug 的成因和修法**。

| # | 症状 | 根因 |
|---|---|---|
| 1 | 三家对同一段宏的输出不同 | 宏展开**时机**不同：解释器懒、编译器和 VM 急 |
| 2 | 报错行号指向了不相干的代码 | 展开宏时重建 AST 节点，把「行号侧表」（`id(语句) → 行号`）弄丢了 |
| 3 | 一个循环结束后，**后面随便哪个错误**都被莫名吞掉 | VM 里 `跳出` 跳走时没发 `POP_TRY`，处理栈上残留的 handler 一直在等着开火 |
| 4 | 同样的症状又来一次 | 带标号的 `跳出` 穿过 `尝试` 时没清处理栈——**同一个坑，第二次踩** |
| 5 | 用户 `定义 长度(...)` 之后，前面那次 `长度(x)` 直接 `UnboundLocalError` | 编译器把内置函数绑在模块级，而整个程序在 `_主()` 里；Python 因此判定它是局部变量 |
| 6 | 报错行号从 1161 跳成 314 | 运算收口到另一个模块后，traceback 里**别的文件**的帧行号撞进了产物的行号映射表 |
| 7 | 跳转指令永远跳到同一处 | VM 的 `回填()` 只改指令的第 1 个参数，而目标被放在了第 2 个 |
| 8 | 缩减器对着一个 56 行的程序一行都删不动 | 「循环安全」检查把 `只要 真` 里的 `真` 当成了循环变量 |

**第 6 条特别值得一提**：它是 `demo13.star` 照出来的——
那个文件一行都没改，但它是个**用星语写的星语解释器**，
内部有自己的 try/catch 和行号，所以对「行号错乱」极其敏感。

> 这类 bug 只有「三个实现 + 一个自举 demo」的组合才照得出来。

## 那它长什么样

```starlang
载入 "标准库.star"

定义 算账(单价, 数量)
    打印 "开始算账"
    返回 单价 * 数量

插入 算账 开头
    打印 "【审计】参数是 " + 单价 + " 和 " + 数量

打印 算账(10, 3)
```

```text
【审计】参数是 10 和 3
开始算账
30
```

> `插入` 是**编译期织进 AST** 的：插进去的代码能直接看到原函数的参数和局部变量，
> 而不需要改原函数一行。这是星语里最不「换皮」的东西。

```starlang
载入 "标准库.star"

# 变量、条件、循环
名字 = "星语"
版本 = 28

如果 版本 >= 20
    打印 "成年了"
否则
    打印 "还小"

遍历 项 于 [1, 2, 3]
    打印 项 * 10

# 函数：默认参数每次调用重算，能引用前面的参数
定义 长方形(宽, 高 = 宽)
    返回 宽 * 高

打印 长方形(3)        # 9
打印 长方形(3, 4)     # 12

# 匿名函数 + 高阶函数
打印 映射([1, 2, 3], 匿名(x) { 返回 x * x })    # [1, 4, 9]

# 闭包
定义 造加器(起点)
    返回 匿名(x) { 返回 起点 + x }
加十 = 造加器(10)
打印 加十(5)          # 15

# 错误处理
尝试
    打印 1 / 0
出错 错
    打印 "抓到了：" + 错
```

**多重循环一次退干净**（标号就是行尾的 `@名字`）：

```starlang
遍历 甲 于 [1, 2, 3] @找
    遍历 乙 于 [10, 20, 30]
        如果 甲 * 乙 > 20
            打印 "第一个超过 20 的是 " + 甲 + "×" + 乙
            跳出 找
```

**宏：参数可以是语句块**（函数做不到）：

```starlang
宏 除非(条件, 动作)
    如果 非 条件
    {
        动作
    }

x = 5
除非(x > 10, {
    打印 "x 不大于 10"
})
```

```text
· 已定义语法「除非(条件, 动作)」
x 不大于 10
```

**钩子：运行期环绕，随时能摘**：

```starlang
定义 干活(东西)
    打印 "正在处理 " + 东西

定义 记日志(参数)
    打印 "  [日志] 参数=" + 参数

注册 之前 干活 记日志
干活("苹果")
拔掉 之前 干活 记日志
干活("香蕉")
```

```text
· 已在「干活」的之前挂上钩子「记日志」
  [日志] 参数=苹果
正在处理 苹果
· 已拔掉「干活」的之前钩子「记日志」
正在处理 香蕉
```

## 它也能跟 Python 互通

```starlang
引入 "math"

打印 math.sqrt(16)      # 4          真属性访问
打印 math.pi            # 3.14159…   常量不带括号
```

反方向：**Python 当宿主，星语当规则引擎**。

```python
import starlang

m = starlang.星语({"单价": 100})
m.执行("总价 = 单价 * 3")
print(m.环境.vars["总价"])          # 300

m.执行('定义 加税(元) { 返回 元 * 1.06 }')
print(m.取("加税")(100))            # 106.0
```

**两个方向都不需要类型转换**——因为星语的 `数/文/表/典` 就是 Python 的
`int/str/list/dict`，从第一天起就没包过壳。

> 这也是它的代价所在：**值模型是借的**。见下面「定位」。

## 怎么跑

```powershell
git clone <本仓库>
cd starlang

python starlang.py   demo1.star     # 解释器
python starlangc.py  demo1.star     # 编译成 Python 再跑
python starlangvm.py demo1.star     # 字节码虚拟机

python 全检.py                       # 一条命令跑完所有验证
```

> ⚠️ 别直接 `python demo1.star`——那是当 Python 跑，会报语法错。
>
> Windows 上如果中文输出乱码：
> `$env:PYTHONIOENCODING='utf-8'; [Console]::OutputEncoding=[System.Text.Encoding]::UTF8`

## 定位：它能干什么，不能干什么

| ✅ 能 | ❌ 不能 |
|---|---|
| 当**读语言实现**的样本（28 步都有「为什么」的注释） | 当生产语言（性能、生态、错误恢复都不够） |
| 当**语义实验台**：改一处规则，跑 1000 个随机程序验一致性 | 当编程入门教材（没有教学优势） |
| 当**差分测试 / 自动缩减**的案例 | 替代 Python 写实际项目 |
| 当**编译器/VM 对照**（三份实现在一个目录里） | 脱离 Python 运行（值模型是借的） |

**「独立」到什么程度**（诚实的阶梯）：

| 级 | 内容 | 星语 |
|---|---|---|
| L0 | 借宿主的**值**和**运算** | ~~✅~~ → Step 28 后运算已收口，值还是借的 |
| L1 | 借宿主的**内存**，值/运算自己定 | 半个（运算自定了，值没） |
| L2 | 自己的运行时（C / Rust 写） | ❌ |
| L3 | 自己的目标代码（汇编 / LLVM IR / WASM） | ❌ |
| L4 | 自举（自己编译自己） | 半个（`demo13` 是解释器自举） |

Step 28 把运算规则收口到 `starlang.py` 里那十几个函数：
`加 / 减 / 乘 / 除 / 余 / 幂 / 取负 / 取正 / 比较 / 取下标 / 设下标`。
**这就是「星语的语义」本身**——将来想换宿主，重写它们就行，解析器一个字不用碰。

### 手册不会腐烂

写文档最怕「代码改了文档没改」——那时候文档比没有更害人。所以立了条硬规矩：

| 标记 | 含义 |
|---|---|
| ` ```星语 ` / ` ```starlang ` | **完整程序，必须能跑** |
| ` ```星语片段 ` | 片段示意，不跑（可能故意报错） |
| ` ```text ` | 程序输出，**必须一字不差** |

`验证文档.py` 把每个代码块抽出来真跑，还核对紧跟其后的输出。
这次写 README 它就抓到两个「跑不起来的例子」，写手册时抓到一个真 bug：
`类型(真)` 返回的是「布」而不是「真假」。

## 已知限制

| 限制 | 说明 |
|---|---|
| 文本不能乘 | `"a" * 3` 报错，用 `文重复("a", 3)` |
| 列表不能相加 | `[1] + [2]` 报错，用 `拼接([1], [2])` |
| 没有 `del` | 用内置 `删键(典, 键)` |
| 点号只到「模块」和「方法」 | `math.sqrt` 行；`人.年龄` 不行，只能 `人["年龄"]` |
| 引入的库只能拿模块级名字 | `json.JSONDecoder` 能造实例，但实例的 `.decode()` 调不了 |
| 不支持关键字参数 | `dumps(配置, ensure_ascii=假)` 用不了 |
| 载入没有命名空间 | 名字全局，跟 `from x import *` 一样 |
| 循环保险丝 50 万圈 | 死循环会主动报错而不是转死机器 |

### 故意跟 Python 不一样的地方

这些不是 bug，是设计决定：

1. **`+` 只要一边是文本就拼接**（Python 里 `"a" + 1` 会报错）
2. **默认参数每次调用重算**（Python 只在定义时算一次）
3. **遍历用快照**（Python 边遍历边改会乱）
4. **`取整` 向零取整**，`四舍五入` 是真的四舍五入（不是银行家舍入）
5. **没有隐式类型转换**：`1 == "1"` 是 `假`
